## 1. 结论

乐乐学采用 **Flutter 做主游戏端**，**微信小程序和公众号做入口**，后端用 **Java**。学生数据只由**私有化部署**的大模型处理。五个学科共用身份、题库、AI 网关、游戏化和内容等共享服务，学科各自独立部署和存储数据。

基础设施按用户规模分四个阶段投入。无用户阶段的投入很小，主要是环境、备案和应用商店账号。用户增长后，成本主要来自 **GPU 和带宽**，这两项随用户数线性增加，是后期的主要成本，也是优化的重点。

## 3. 架构

```
Flutter 客户端（Android / iOS / Web）       微信小程序 / 公众号（入口导流）
                  │                                     │
                  └──────── API 网关（鉴权、限流、路由）────┘
                                     │
   共享服务：身份 | 题库 | AI 网关 | 游戏化 | 内容
                                     │
   学科服务：英语 | 数学 | 语文 | 物理 | 化学（各自独立数据库）
                                     │
   事件总线（答题、通关、升级、成就、掌握度变化）
                                     │
   数据平台（实时统计、掌握度计算、学情报告、离线分析）
```

**要点**
- 学科服务之间不直接访问彼此的数据，只通过网关和事件总线通信。
- 共享服务与学科无关，用学科编码区分数据。由共享能力架构师（issue #23）负责。
- AI 网关统一对接模型。业务服务不直接调用模型。

## 4. 基础设施与投入

### 4.1 估算假设（需用真实数据校准）

| 假设 | 数值 |
| --- | --- |
| 峰值并发 | 日活用户的约 10% |
| 请求频率 | 每个在线用户约每 5 秒 1 次 |
| 每用户每日 AI 调用 | 早期 5 次，增长期 8 次，规模期 10 次 |
| 每次 AI 调用平均 token | 约 1,500 |
| AI 调用中落到模型的比例 | 约 20%（其余由题库、缓存解决） |
| 资源流量 | 首次进入约 20MB，之后约 2MB/日 |

### 4.2 分阶段规模

| 项目 | 阶段 0：无用户 | 阶段 1：约 1 千日活 | 阶段 2：约 1 万日活 | 阶段 3：约 10 万日活 |
| --- | --- | --- | --- | --- |
| 环境 | 开发、测试、预发、生产各一套 | 同左 | 同左，生产多可用区 | 同左，生产多可用区 + 灾备 |
| 应用服务器 | 2 台（最小规格） | 3 台 | 6 台 | 20–30 台（弹性伸缩） |
| 数据库 | MySQL 单机 + 备份 | 主从 | 分库 2–4 个，每库主从 | 分库分表 8 个以上，主从 |
| 缓存 | 单实例 | 主从 | 集群 | 集群，多节点 |
| 消息队列 | 单机 | 最小集群 | 集群 | 集群 |
| GPU（私有化推理） | 0，PoC 时临时租用 | 1 卡 | 2–3 卡 | 10–15 卡（以 benchmark 为准） |
| 对象存储 | 约 100GB | 约 500GB | 约 2TB | 10TB 以上 |
| CDN 带宽 | 约 5 Mbps | 20–50 Mbps | 100–200 Mbps | 500 Mbps–1 Gbps |
| API 公网出口带宽 | 约 5 Mbps | 约 10 Mbps | 约 50 Mbps | 200–300 Mbps |
| 峰值 QPS（估算） | 低于 10 | 约 20 | 约 200 | 约 2,000 |
| 每日 AI 调用（估算） | 0 | 约 5,000 | 约 8 万 | 约 100 万（约 20% 落到模型） |
| 安全与监控 | 基础监控、备份 | 日志与告警 | WAF，等保测评 | 完整灾备与演练 |
| CDN 流量费（估算） | 约 0 元 | 约 35 元 | 约 350 元 | 约 3,500 元 |
| GPU 费用（估算） | 0（PoC 临时租用） | 约 1,900 元（1 卡） | 约 3,800–5,700 元（2–3 卡） | 约 19,000–28,500 元（10–15 卡） |
| 服务器、数据库、缓存、队列、存储、公网带宽 | 待运维报价 | 待运维报价 | 待运维报价 | 待运维报价 |
| **已估算合计**（不含待报价项） | **约 0 元** | **约 1,935 元** | **约 4,150–6,050 元** | **约 22,500–32,000 元** |

**费用依据**
- CDN 流量：阿里云官网公示的中国大陆单价为 0.04 美元/GB（0–50TB 阶梯），按 7.2 汇率折算约 0.29 元/GB。资源包比按量付费更便宜。流量按每日资源流量（每用户约 2MB）加每日新用户首次下载（每人约 20MB）估算。
- GPU：以 T4（16GB）包月约 1,878 元/卡作参考，这是第三方整理的阿里云价格，需以官网和运维报价为准。选定模型后，卡型不同单价差异很大。
- 服务器、数据库、缓存、队列、存储、带宽：单价随规格、地域和计费方式变化大，目前没有可靠的标准价，标注为待报价。
- 合计只包含已估算的项目，实际总费用会更高。
- 服务商：以上估算以阿里云公开价格为依据，但服务商尚未确定（见待决事项 P3）。确定服务商后，需要按其报价替换这些数字。

### 4.3 投入变化的规律
- **固定成本**：环境、备案、应用商店账号、监控。无用户阶段主要是这部分，金额低。
- **阶梯成本**：应用服务器、数据库、缓存。跨过一个用户量级时才扩容。
- **可变成本**：GPU 和带宽，随用户数和调用量线性增长，是后期的主要成本。
- **控制成本的关键**：让题库、缓存和小模型处理大部分请求，只把少量复杂任务交给大模型。这是 AI 只有约 20% 落到模型的前提。

### 4.4 无用户阶段必须完成的投入

| 项目 | 说明 | 备注 |
| --- | --- | --- |
| 域名与 ICP 备案 | 境内服务器对外提供网站服务必需 | 周期较长，需提前办理 |
| 微信小程序注册与认证 | 入口端上线必需 | 费用以官方为准 |
| 苹果开发者账号 | iOS 上架必需 | 年费，以官方为准 |
| 安卓应用商店账号 | Android 上架 | 各商店政策不同 |
| 云账号与四套环境 | 最小规格 | 运维报价后填入 |
| 测试用合成数据 | 开发阶段不使用真实学生数据 | 由产品设计师与架构师准备 |

## 5. 合规与安全

- 学生身份、学校、联系方式、家长信息不进入任何模型。
- 学生对话和学习行为只由私有模型处理，不用于训练外部模型。
- 面向公众的生成式 AI 服务，需按国家规定完成备案。
- 隐私政策、用户授权、数据留存期限由项目方自行制定并落实。
- 等级保护：运维确认等级，并在上线前完成测评。

## 6. 迭代计划

| 阶段 | 基础设施 | 目标 |
| --- | --- | --- |
| 阶段 0：可玩原型 | 阶段 0 | 选数学学科，跑通关卡、动画、题库和规则判题，暂不接入 AI |
| 阶段 1：接入 AI | 阶段 0 → 1 | 接入私有模型，上线智能出题（经审核入库）和即时讲解 |
| 阶段 2：扩展学科 | 阶段 1 → 2 | 其余学科复用共享服务，上线小程序入口 |
| 阶段 3：高并发与数据 | 阶段 2 → 3 | 拆分服务、接入消息队列和缓存，压测，启用分库分表与弹性扩容 |

## 7. 风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 私有模型的 GPU 数量估计偏差 | 成本偏高或服务能力不足 | 上线前做 benchmark，按实测调整 |
| 小程序跳转 Flutter 客户端的方式不可行 | 入口体验受影响 | 先做 PoC，备选方案待定 |
| 备案周期长 | 上线推迟 | 无用户阶段第一时间办理 |
| AI 输出不准确 | 学生学到错误知识 | 题库审核 + 教材检索 + 人工抽检 |
| Flame、Rive 性能不足 | 动画卡顿 | 上线前在中低端机上做 PoC |
