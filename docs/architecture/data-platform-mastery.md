# 数据平台：掌握度计算与 MasteryChanged 发布（草案 v0.1）

关联：#92（数据平台实现）、#1（裁定：掌握度事件发布方与投递语义）、#23（共通，事件字段）、report-v3 第 3 节。
状态：草案，由数据平台对话起草，待项目总监审核。未经审核前不开发。
记录人：数据平台（【开发｜数据平台｜#92】）

## 1. 范围

本草案只覆盖最小切片：
- 输入：学科服务产生的答题结果（学科、知识点编码、用户、对错、时间）。
- 计算：按知识点计算掌握等级。
- 输出：掌握等级首次达到时发布 `MasteryChanged` 事件。
- 首次可用：英语第一单元接入时（#1 裁定）。

不在本草案内：学情报告、离线分析、死信界面、推荐回写（分别排后续切片）。

## 2. 事件契约

字段以 `packages/shared/lib/core/mastery_changed.dart` 现有草案为准，本草案不另定义字段：

| 字段 | 说明 |
| --- | --- |
| `eventId` | 全局唯一，消费方去重的键 |
| `userId` | 学生 |
| `subject` | 学科编码 |
| `knowledgePointId` | 知识点编码（编码规则待与 #23 对齐） |
| `level` | 掌握等级，含义由学科定义（英语：1★ 识别、2★ 应用、3★ 迁移） |
| `achievedAt` | UTC 时间 |

业务唯一键：`(userId, subject, knowledgePointId, level)`。同一键只产生一次「首次达到」语义，经验发放以此为准，不以 `eventId` 为准。

## 3. 投递语义（#1 已裁定）

- 至少一次投递。
- 消费方以 `eventId` 去重；经验发放另以业务唯一键保证只发一次。
- 失败重放：保留期由后台配置；消费方记录已处理位置。
- 无法处理的消息进入死信队列，由数据平台负责人查看。

## 4. 掌握等级判定

沿用共享游戏化规则（物理、英语设计中已引用）：

- 1★：识别正确率 ≥80% 且不少于 5 题。
- 2★：应用正确率 ≥80% 且不少于 5 题。
- 3★：新语境正确率 ≥80%，且间隔复习通过一次。

判定数值由学科设计决定，数据平台只执行判定。`gamification.md` 当前不在仓库中，判定规则以学科设计文档为准，待共通（#23）补充后再核对。

## 5. 待决事项（需项目总监决定，影响共通与各学科）

1. **事件总线选型**：
   - 方案 A：托管消息队列（运维少，成本随用量增长，需确认）。
   - 方案 B：自建 Kafka 或 RabbitMQ（灵活，运维成本高）。
   - 方案 C（建议用于第一切片）：数据平台库内的发件箱表（outbox），由轮询发布；与学科库隔离。待流量与真人确认成本后，再迁移到消息队列。
2. **保留期**：默认建议 7 天，由后台配置；死信保留期待定。
3. **知识点编码对接**：需与 #23 对齐编码格式，否则无法做去重键。
