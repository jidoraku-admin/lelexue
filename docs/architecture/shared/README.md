## 1. 范围与边界

共享能力与学科无关，只通过学科编码区分数据。

| 服务 | 文档 | 职责 | 数据存放 |
| --- | --- | --- | --- |
| 身份 identity | `identity.md` | 账号、登录、家长与学生关系、席位、权益查询 | 共享身份库 |
| 题库契约 question-bank | `question-bank.md` | 题目模型、校验、审核状态机、检索接口 | **题目内容存各学科自己的数据库**；共享层不集中存题 |
| AI 网关 ai-gateway | `ai-gateway.md` | 统一入口，所有调用走私有化模型，限流、审计、降级 | 只存调用元数据，不存学生原文 |
| 游戏化 gamification | `gamification.md` | 消费掌握度等事件，计算经验、徽章、粟米；提供展示组件 | 共享游戏化库，只存奖励结果 |
| 内容 content | 未写 | 版本化内容包发布（排期后再写） | — |

### 1.1 学科独立存储（项目说明与 report-v3 第 3 节）

- 每个学科有自己的数据库。学习进度、答题记录、掌握度、题目内容都存在学科库中。
- 共享层只保存与学科无关的数据：身份、席位、权益、奖励结果。
- 共享层通过学科编码引用学科数据，不读取学科库。需要学科数据时，由学科服务通过事件或接口提供。

### 1.2 学段字段（共通对话定义，真人 2026-11-22 委托）

| 字段 | 取值 | 说明 |
| --- | --- | --- |
| `stage` | `primary`（小学）、`junior`（初中）、`senior`（高中） | 学段 |
| `grade` | 1–12 整数 | 小学 1–6，初中 7–9，高中 10–12。例如三年级为 3，初二为 8，初三为 9 |
| `volume` | 1 或 2 | 册次：1 为上册，2 为下册。化学初三上为 `stage=junior, grade=9, volume=1` |

起步学段以 0007 为准（英语、数学、语文小学三年级；物理初二上；化学初三上）。

### 1.3 共通与学科的分界（项目总监裁定，真人 2026-11-22 委托）

- **共享**：身份、席位、权益、题库契约与审核流程、AI 网关、游戏化的经验与徽章规则、积分规则、展示组件（`XpBar`、`LevelBadge`、`BadgeWall`、`CoinCounter`、`RewardToast`）。
- **留在学科内**：玩法、关卡、故事、Boss 战等。例如英语的 Boss 战组件属于英语，不进入共享层。

## 2. 共同约束

1. **学生数据只走私有化模型。** 网关不提供外部模型通道；路由由网关配置决定，调用方无法选择或覆盖（见 `ai-gateway.md`）。
2. **学科隔离。** 学科数据只在学科库中。共享服务只接收事件与引用，不读取学科库。
3. **未成年人规则未经法务复核不上线。** 相关能力只做到接口与开关层面，不启用。
4. **规则数值后台配置。** 奖励次数、佣金、积分兑换、配额等数值不写死在代码中（见 0004）。
5. **不做结果承诺。** 文案不得暗示考试成绩或保证提分（见 0002、0006）。
6. **依赖顺序。** 学科对话使用共享能力前，先在 #23 提需求；共通对话回复接口与排期后，学科才能在代码中依赖。

## 1.4 共通范围（#23 项目总监更正，2026-11-22 06:05，共通据此执行）

- **共通（确定）**：身份与权益（账号、母子关系、席位、权益查询、服务间鉴权），AI 网关（私有化路由、限流、审计）。
- **共通（候选，待学科确认）**：掌握度事件的最小 schema（`eventId`、`userId`、`subject`、`knowledgePointId`、`level`、`achievedAt`），`level` 的含义由学科定义（1★ 识别、2★ 应用、3★ 迁移）。
- **共通（玩法框架）**：0010 的 game kit，首批配对、下落选择、出牌、猜测；拖拽搭建、排序为第二批（见 `game-kit.md`）。
- **不共通**：题库数据模型与题目内容、游戏化的经验与徽章与积分规则、展示组件、判题规则、语音与数据加载。
