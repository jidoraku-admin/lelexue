# 共享 AI 网关 ai-gateway（接口草案 v0.2）

> 负责：共通对话（#23）。状态：修订稿，待项目总监复审。服务间鉴权见 `ai-gateway.md` 第 8 节。
> 修订要点：取消调用方自报的数据分级，所有调用固定走私有化模型；模型型号与部署位置待真人选择。

## 1. 目标

- 所有学科通过同一入口调用大模型，统一鉴权、限流、审计、降级（report-v3 第 3 节：业务服务不直接调用模型）。
- **学生数据只由私有化部署的模型处理**（项目说明，report-v3 D6）。
- 网关**没有外部模型通道**。路由在网关内部固定，调用方无法选择或覆盖。

## 2. 分层

```text
学科服务 ──> AI 网关 ──> 私有化模型（vLLM 推理服务）
                 │
                 ├── 鉴权与配额（按 UserId、SubjectCode）
                 ├── 字段过滤（拒绝身份、学校、联系方式、家长信息）
                 ├── RAG（按学科隔离的索引）
                 └── 审计（只记元数据）与降级
```

## 3. 接口

```text
AI.complete(request) -> CompletionResult
AI.embed(subject, texts[]) -> Vector[]
AI.retrieve(subject, query, filter) -> Chunk[]
AI.reportFeedback(callId, rating, reason?) -> void      // 不含个人信息
```

```text
CompletionRequest {
  subject: SubjectCode        // 必填，用于隔离与审计
  userId?: UserId             // 学生相关调用时填写，仅用于配额与审计
  purpose: string             // 用途编码，如 hint、explain、item_gen
  prompt: ...
  limits: { maxTokens, timeoutMs }
}
```

- 已删除 `dataClass`。调用方不声明数据级别，网关对所有请求执行同一条私有化路由。
- `embed` 同样只走私有化模型。
- 请求中若出现禁止字段（学生身份、学校、联系方式、家长信息），网关直接拒绝，并记录一次校验失败（不记录字段值）。

## 4. 数据与日志

- 日志只记录调用元数据：学科、用途、耗时、token 数、结果状态。
- 不记录原始学生输入与模型输出。
- 学生对话与学习行为只由私有模型处理，不用于训练外部模型（report-v3 第 6 节）。

## 5. 限流与降级

- 按 `UserId` 与 `SubjectCode` 配额，数值后台配置。
- 模型不可用时返回 `DEGRADED`。学科游戏不得因模型故障而阻塞，由学科决定前端表现（如预置提示）。
- 题库的题目生产是离线批处理，与在线调用分开配额。

## 8. 服务间鉴权（#1 裁定，2026-11-22 14:59）

- **方式**：内网服务令牌。每个服务持有独立密钥，由部署环境注入，不写入代码或仓库。
- **可达范围**：服务只在内网可达，不提供公网入口。学生端只通过学科服务访问 AI 功能。
- **调用方身份**：只接受持有有效服务令牌的服务。令牌缺失、过期，或与请求中的 `subject` 不匹配，一律拒绝，并记录拒绝次数（不记录请求内容）。
- **学生端不直连网关**：学生的会话令牌由身份服务签发与校验，网关不接收学生端的原始令牌。
- **userId 的来源**：学科服务把已校验的 `userId` 放入请求，网关只用于配额与审计，不用于鉴权。
- **事件总线**：数据平台只通过事件总线（发件箱）通信，不发起 HTTP 调用，不适用本节的令牌校验。若数据平台需要通过 HTTP 调用网关或身份服务，同样使用内网服务令牌。
- **轮换**：密钥轮换由部署环境负责，本文档不规定周期。
