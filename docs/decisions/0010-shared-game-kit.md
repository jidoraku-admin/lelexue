# 0010 共通玩法框架（game kit）与学科选用（2026-11-22）

- 决定人：项目总监（真人 2026-11-22 指示：按项目总监的想法定）
- 分级：中事（开发架构，不改变学习路径与奖励规则），由项目总监决定
- 关联：#23（共通）、#7（英语）、#68（六对话协调）、0009（先做第一单元，功能复用，数据替换）

## 背景

英语的玩法代码（配对、下落选择、出牌、猜测）约 1,450 行，其中大部分是与内容无关的规则与界面骨架。其他学科若各自实现，会重复这部分代码。但英语的实现依赖英语的 `Word` 类型与语音、数据加载，不能直接共用。

## 结论

1. **共通提供玩法框架（game kit），放在 `packages/shared` 的玩法包中。** 首批只包含四个通用玩法：配对、下落选择、出牌、猜测。拖拽搭建、排序等需求经学科确认后再加入。
2. **学科按需选用。** 学科只写内容适配层（题目来源、词与题的映射、学科的特殊规则），不重写玩法规则。
3. **框架不认识学科。** 框架只接收题干、正确答案、干扰项、反馈文本；只上报作答的对错与用时，不计分，不调用语音与数据加载，不引用经验、掌握度与奖励规则。
4. **只抽取至少两个学科会用的玩法。** 学科独有的玩法（如物理的模拟实验、化学的装置正确性判断、英语的语音相关玩法）留在学科内。
5. **先英语、后其他学科。** 英语在第一单元上完成抽取并验证；框架通过验证后其他学科才能采用。框架的测试由共通负责，学科的测试只覆盖内容与适配层。
6. **与 0009 一致。** 框架的验收标准是：第一单元调通后，第二个单元的数据导入不改代码即可运行。

## 影响

- 英语需要把玩法中对 `Word` 的依赖改为通用题目结构，并把语音与数据加载改由调用方注入。这是迁移的主要工作量。
- 共通的 P1 工作改为玩法框架，原计划中的展示组件与游戏化骨架暂缓（见 #23 的更正）。
- 对英语的玩法改动不改变已经真人确认的功能范围（#7）。
