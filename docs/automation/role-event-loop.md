# 岗位事件循环规则

状态：待真人审核；需仓库管理员添加 `ANTHROPIC_API_KEY` 密钥后启用。

## 一、触发
- 技术总监在 issue 或 PR 上的评论（签名 `【技术总监｜学科｜issue号】`）或 PR 审核，自动唤起对应学科的产品设计师。
- 设计师自己的回复不触发任何岗位，防止自我循环。

## 二、循环上限
- 同一学科的自动循环最多 3 轮。超过后停止自动唤起，在 issue 中留言交由技术总监处理。
- 每轮设计师必须在 issue 中回复签名与修改结果，循环计数以此为依据。

## 三、设计师的权限
- 工作流内的范围校验（path-check）：推送的改动若不在 docs/product/ 内，校验失败并停止。
- 可以：修改本学科的设计文档（如 `docs/product/`），推送到自己的功能分支，在 issue 中回复。
- 不可以：合并 PR，修改 `stage:*` 标签，做定稿、验收或推广决定，修改其他学科或共享目录。

## 四、停止条件
- 技术总监标记 `stage:design-final`，循环结束，交真人定稿。
- 任何一方在 issue 中写"暂停"，立即停止自动唤起。

## 五、成本与监控
- 每次唤起消耗模型调用，需在仓库 Actions 中设置用量上限。
- 每日汇总（#25）列出本日自动循环次数。

## 六、局限
- 权限靠工作流的校验与提示词约束，不是 GitHub 分支保护的强制限制。建议仓库管理员为该分支设置保护规则。
- 每个学科需复制一份工作流，只改 env 配置。
