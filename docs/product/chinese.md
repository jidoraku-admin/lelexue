## 1. 定位与目标

**产品定位**：面向 3 年级起的学生，用于语文日常识字、词语、句子与阅读的学习与复习，内容与人教版（2022 修订）三年级上册保持一致（见第 3 节）。

**每天的学习闭环**

1. **预习**：读一段本课的原创短文或动画故事，接触本课的生字与词语语境。
2. **识字与新学**：认读、书写、偏旁结构、词语与句子的学习，每个知识点有明确的掌握目标。
3. **练习**：针对刚学内容做分层练习（识记、应用、迁移），即时反馈并讲解错因。
4. **复习**：按间隔复习安排，把旧字词在合适的时间重新出现。
5. **验收**：单元结束时做单元验收，结果决定是否进入下一单元。

**设计目标**

- **过程指标**：覆盖率、复习保持率、单元测分数率。本稿不写任何成绩结果承诺，遵循 `docs/decisions/0002` 与 `0006`。
- 替代线下重复抄写、机械默写的预习与复习流程，让学生每天有可执行的任务。
- 每个环节都能对应到教材的某项活动或某个生字词，内容不超出教材范围，超出部分按 0006 第二节处理。

---

## 2. 学习内容与玩法

| 环节 | 学什么 | 形式 |
| --- | --- | --- |
| 识字 | 认读、字形、部首 | 找字、拼字、收集字卡，解锁故事章节 |
| 偏旁拼装 | 字形结构 | 拖动偏旁组成新字，错误时给出结构提示 |
| 词语 | 词义、近反义词、搭配 | 词语接龙，限时完成，连续正确加分 |
| 句子 | 句子成分、标点、词序 | 调整词序让句子通顺，错误给出语法提示 |
| 阅读 | 短文理解、段落大意 | 读完短文回答选择题，收集线索推进剧情 |
| 口语 | 朗读、口语交际 | **首版暂缓**。依赖语音能力，不在共通玩法框架内（0010） |

**错误处理**：错误不扣分，给出一条原因解释，允许立即重试。

**节奏**：每次学习约 10 分钟，每个环节有一个明确的小目标。

## 4. 故事与角色（草案）

- **世界观**：一座会说话的"字之森"，树上挂着字的种子，学生帮助森林居民把字种回枝头。
- **主角**：一位 3 年级的小向导（名字与形象待定），陪伴学生完成每一章。
- **故事服务知识点**：每一章的剧情只用本章的生字和词语，超出部分不出现。
- **首切片三章（第 1 单元）**：第 1 章对应"大青树下的小学"，主角带学生认识"字之森"的第一棵树；第 2 章对应"花的学校"，森林里的花需要按词语重新排列；第 3 章对应"不懂就要问"，遇到不懂的字时向森林居民请教。每章的生字与词语由本课生字表确定。
- **不做虚拟陪伴**：故事角色不做成陪伴、亲密关系形态，避开 `docs/decisions/0006` 第三节提到的合规风险，待法务确认。

## 5. 未成年人与合规

本子系统面向未成年人，遵循以下约定，法务复核完成前不上线：

- 学生账号从属于家长账号，不能独立注册、付费或开启推送（参照英语的共享身份需求，见 #23 的评论）。
- 不收集与学习无关的个人信息；个人信息条款需法务复核。
- 未成年人模式、单日使用与消费限制，依 `docs/decisions/0006` 第三节的法务事项执行。
- **零奖励原则**：奖励只与掌握挂钩，不与邀请、分享、注册、付费或班级人数挂钩。
- 学生数据只由私有化部署的模型处理，公有 API 不接收学生个人信息。

## 6A. 玩法需求（#72 共识请求，对应 0010）

首批框架包含配对、下落选择、出牌、猜测；拖拽搭建、排序需两个或以上学科确认后进入第二批。

| 语文玩法（第 2 节） | 对应框架玩法 | 说明 |
| --- | --- | --- |
| 识字找字 | 猜测、配对 | 由偏旁或拼音线索选出目标字；字与拼音、字与词义配对 |
| 偏旁拼装 | 拖拽搭建（第二批候选） | 拖动偏旁组成新字，需要拖拽能力 |
| 词语接龙 | 出牌 | 每回合出一个能接上的词，按规则判对错 |
| 句子词序 | 排序（第二批候选） | 调整词序使句子通顺，需要排序能力 |
| 阅读选择题 | 猜测 | 读完短文后选择答案 |
| 限时识字（可选） | 下落选择 | 字或词下落，玩家在时限内选出正确读音或释义 |

- **需要共通的部分**：配对、下落选择、出牌、猜测的玩法规则与界面骨架；拖拽搭建、排序待第二批确认。
- **留在学科内的部分**：生字与词语题目内容、偏旁与字形结构规则、语法提示文案、错因解释、学科的计分与奖励（框架不计分，见 0010）。
- **不在框架内**：朗读评分与语音（首版暂缓）。

| 维度 | 结论 | 说明 |

| 技术 | 通过 | 首切片只用框架的四个玩法（配对、猜测、出牌、下落选择，0010），不用拖拽、排序与语音；单元数据以结构化文件提供，不写死单元（0009）。设计上不依赖未定义的接口；框架与题库的接入是进入开发（stage:dev）的前置条件，不属于设计阶段的通过条件。 |
