# 英语设计稿 v2（三年级上 Unit 1–3 试玩，游戏化与动画故事）

- 状态：stage:design（草稿，已完成项目总监自审，待真人定稿）
- 依据：0006 第一节试玩反馈；0006 第六节官方单元名（Unit 1 Greetings、Unit 2 School things、Unit 3 Toys）
- 范围：本稿只覆盖 Unit 1–3 的游戏与故事，Unit 4–6 沿用同一结构，不在本稿内设计。

## 一、回应四点反馈

| 反馈 | 本版怎么改 |
| --- | --- |
| 功能简陋，需要细化 | 单元地图改为村庄地图：每个单元解锁一处建筑；关卡带星级、角色贴纸、进度条；错题进入补救关，不直接扣分。 |
| 没有游戏，学习必须以游戏形式进行 | 每关改为小游戏玩法：翻卡配对、对话闯关、情境选择。游戏是学习的主要形式，不是附加的奖励。 |
| 没有动画故事 | 每单元一集 30 秒动画开场，关卡之间用角色对话过场，通关后播放结业小片段。 |
| 不够生动有趣 | 角色有表情与语音，答对和答错有不同的反馈动效与音效；错误时角色给出提示，不说"错"，只说"再试一次"。 |

## 二、世界观与故事主线

- 地点：叽叽村小学。玩家是刚转来的新同学，可以起名字。
- 角色（沿用 Unit 1 的小栗、阿圆、团团，Unit 2–3 加入小猪、小鸭、小老鼠、小牛）：
  - 小栗：好奇、爱问问题，是玩家的第一个朋友。
  - 阿圆：爱分享，经常带点心。
  - 团团：爱运动，活泼闹腾。
- 主线：玩家在叽叽村开学，逐单元认识新朋友，帮他们解决生活里的小问题，学会英语的打招呼、借用东西、玩耍和分享。

各单元的故事：

| 单元 | 故事 | 玩家学会 |
| --- | --- | --- |
| Unit 1 Greetings | 开学第一天，小栗在校门口迎接大家。 | 问候与自我介绍 |
| Unit 2 School things | 小猪的铅笔盒找不到了，小鸭需要借尺子，玩家帮忙找回文具。 | 借用、道谢、道歉 |
| Unit 3 Toys | 玩具角里，小老鼠和小牛一起玩，学会分享和请求一起玩。 | 问玩具、请求、夸奖 |

## 三、单元结构（每单元一致，换数据即可）

1. 开场动画（30 秒，4 个镜头）。
2. 认词关：翻卡配对，每关 8 词，两关为一组。
3. 句型关：对话闯关，角色说一句，玩家选回应。
4. 运用关：情境选择，帮角色说对话。
5. 单元挑战（Boss）：12 题的"故事挑战"，通过线 80%。
6. 复习关：Boss 后复习错题；没有错题则复习 6 个已学词。
7. 结业小片段：角色完成一件事，村里的建筑亮起来。

失败处理：Boss 没过，进入补救关（补救关全部答对才能再挑战 Boss）。补救关不扣星，只是多练一次。

## 四、动画与美术

- 角色：沿用已生成的原创 SVG（小栗、阿圆、团团、小猪、小鸭、小老鼠、小牛等）。动画技术选型未定（Rive、Lottie 或 Flutter 自绘），需做一个 PoC 后再定，见第六节。
- Unit 1 开场分镜（示例）：
  1. 村口校门，阳光，小栗跑过来。
  2. 小栗挥手："Hi!"（语音）。
  3. 阿圆和团团加入，三人打招呼。
  4. 镜头拉远，村庄地图的第一座建筑亮起。

## 五、四维自审

| 维度 | 结论 | 说明 |
| --- | --- | --- |
| 技术 | 中 | 数据驱动与分层已在 Unit 1–2 验证；动画技术未选型，未做 PoC。 |
| 趣味 | 中高 | 游戏循环完整（认词、对话、情境、Boss、补救），但小游戏的具体手感未试玩验证。 |
| 故事 | 中 | 主线与三个单元故事已定；各镜头的台词与分镜未写完整，Unit 3 的台词需要再打磨。 |
| 吸引性 | 待验证 | 角色与配色已有，动画和音效未做，无法判断是否真的生动。 |

自审结论：技术、故事、吸引性三项还不能判定为"可定稿"。定稿前需要补的是：动画 PoC、Unit 3 台词、一版可点击的小游戏原型。补完后再次自审，再交真人定稿。

## 六、需要真人决定的事项（大事）

1. 世界观（叽叽村）与玩家身份是否采用。
2. 角色配音用语音合成还是真人录音（影响成本与品质）。
3. 补救关"Boss 锁"的规则是否保留。

动画技术选型不属于真人决定，由项目总监在 PoC 后选定。
