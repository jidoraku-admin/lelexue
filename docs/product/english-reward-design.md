# 英语子系统奖励体系设计

- 版本：v0.1
- 状态：独立设计稿，待技术总监与真人最终审核
- 负责人：英语子系统产品设计师
- 关联文档：`english-game-design.md`（游戏设计，v0.2）、`english-viral-growth.md`（裂变设计，v0.2）、`english-user-attraction.md`（吸引与留存，v0.3）、`english.md` §9（平台规则）

---

## 0. 这份文档解决什么问题

游戏设计中的徽章、装饰、词卡图鉴、伙伴技能卡已经有了奖励的雏形，但没有系统地回答三个问题：奖励给什么、什么时候给、给多少。本文把奖励体系完整定义下来，并明确哪些奖励不能给。

**边界先定死**：奖励只与学习行为本身挂钩（学会了什么、做得怎样），不与邀请、分享、注册、付费、班级人数挂钩。这一条来自微信小程序的利益诱导分享规则，也来自未成年人保护与学校的管理要求（见 `english-viral-growth.md` §3.6 与 §8）。

---

## 1. 设计原则

1. **奖励掌握，不奖励行为**：奖励的依据是知识点达到的星级、通过的 Boss、完成的补救，而不是点了多少次、停留多久、拉了多少人。
2. **奖励可见，但不可交易**：奖励是孩子的成就展示，不能兑换现金、实物或学习之外的利益，也不能转让。
3. **装饰为主，能力为辅**：大部分奖励是装饰性的，只有伙伴技能卡这一类影响练习体验，且不影响计分（见游戏设计 §7.4）。
4. **不与成绩挂钩**：产品的奖励不计入学校的成绩、评优或综合素质评价。产品不向学校提交任何奖励记录用于评价。
5. **节奏克制**：奖励弹窗有每日上限，不因连续登录或停留时长增加奖励。
6. **随机只用于无关紧要的装饰**：可以有小概率的装饰掉落以增加惊喜感，但不能付费获得，不能用于学习能力类奖励，且随机结果要透明（见 §4）。

---

## 2. 奖励类型

| 类型 | 具体内容 | 获得条件 | 性质 |
|---|---|---|---|
| 词卡图鉴 | 每个词的图鉴卡：1★ 线条画，3★ 完整彩色卡 | 对应知识点达到 1★ 或 3★ | 收藏，装饰 |
| 徽章 | 如"一次通过 Boss""补救后逆袭""用上了三次暴击" | 对应的掌握表现 | 成就展示 |
| 称号 | 如"过去时小能手""句型探险家" | 同一类知识点达到 2★ 的数量 | 成就展示 |
| 小乐装饰 | 服饰、配件、表情 | 乐乐等级达到一定数值，或完成季终 Boss | 装饰 |
| 地图装饰 | 区域内的建筑、植物、灯饰 | 单元 Boss 通过后解锁 | 装饰 |
| 伙伴技能卡 | 如"小乐的放大镜"，只在据点练习与复习中使用 | 对应知识点达到 2★ | 能力，不影响计分 |
| 故事彩蛋 | 额外的小短片或台词彩蛋 | 对应故事全部观看，且完成对应据点 | 内容，不影响计分 |
| 季徽章 | 每季一个，与季终 Boss 绑定 | 通过季终 Boss | 成就展示 |
| 老师认可 | 老师在课堂上公开表扬，或发放电子认可卡 | 老师自行决定，但依据必须是学习表现 | 非产品奖励，不计入评价 |

**关于老师认可**：电子认可卡由老师生成，内容只写学习表现，例如"本周通过了三个句型的应用练习"。认可卡不附带任何分数或评优标记，也不由产品向学校提交。

---

## 3. 奖励触发规则

| 触发事件 | 奖励 | 说明 |
|---|---|---|
| 据点达到 2★ | 词卡彩色化（对应词）、伙伴技能卡 | 每个据点只触发一次 |
| 据点达到 3★ | 暴击动画加长、图鉴完整版 | 只影响视觉 |
| 单元 Boss 通过 | 地图装饰、单元徽章 | 同一单元只触发一次 |
| 弱点关通过后 Boss 通过 | 徽章"补救后逆袭" | 只在首次通过时触发 |
| 季终 Boss 通过 | 季徽章、小乐装饰、故事彩蛋 | 每季一次 |
| 乐乐等级提升 | 装饰解锁 | 等级只由掌握的知识点数量决定 |
| 班级集体目标达成 | 班级徽章，由老师在课堂上公开表扬 | 见 §3.1 |

### 3.1 班级集体目标

- **目标依据**：班级内所有已加入学生的掌握进度，以每人的掌握知识点数量计算，取班级平均。
- **与人数无关**：班级人数的多少不影响目标，不设"满员奖励"，不设"人数达到 N 解锁"。
- **与邀请无关**：目标达成不依赖谁邀请了谁，邀请行为不计入任何集体目标。
- **展示方式**：班级徽章只显示班级名称与达成时间，不显示个人排名，不显示谁做得多、谁做得少。
- **老师的使用**：老师可以在课堂上表扬全班的进步，表扬内容由老师自己决定。

## 4. 随机与透明度

- **允许的随机**：装饰类奖励（如小乐的配件、地图的小装饰）可以有小概率的随机掉落，增加惊喜感。
- **不允许的随机**：任何学习能力类奖励（伙伴技能卡、故事彩蛋的解锁条件）、任何付费随机、任何与邀请或分享有关的随机。
- **透明**：随机掉落的概率在应用内公开，孩子与家长都可以查看。
- **不做保底诱导**：不设"再抽 N 次必得"的机制，避免变成抽卡。

---

## 5. 节奏与防过度

- **每日奖励弹窗上限**：每天最多 5 个奖励弹窗，超过的奖励进入"收藏箱"，孩子可以随时查看，不弹窗打断。
- **不随时长增加**：奖励的获得只与掌握有关，不因停留时长增加。
- **不设连续奖励惩罚**：中断学习不失去已获得的奖励。
- **奖励不作为打开应用的理由**：推送文案不提及奖励，推送只提醒故事与复习（见 `english-user-attraction.md` §3.3）。

## 6. 数据与护栏

### 6.1 埋点

| 事件 | 说明 |
|---|---|
| `reward_earned` | 获得奖励（附类型与触发事件） |
| `reward_view` | 查看收藏箱 |
| `class_goal_reached` | 班级集体目标达成（只记录班级与时间） |
| `teacher_recognition_sent` | 老师发出认可卡（只记录数量，不记录内容） |

### 6.2 指标与护栏

| 指标 | 定义 | 目标 |
|---|---|---|
| 奖励与掌握的关联 | 获得 2★ 以上的知识点中，有奖励触发的比例 | 100%（奖励必须来自掌握） |
| 收藏箱查看率 | 每周查看收藏箱的用户比例 | 设计初值 ≥ 40%，4 周后校准 |
| 护栏：掌握率 | 奖励功能上线前后，同样知识点的掌握率 | 不下降 |
| 护栏：投诉率 | 与奖励相关的投诉占比 | 低于 0.1% |

**注意**：奖励的目标不是让孩子多领奖，而是让孩子为学会而高兴。如果收藏箱查看率高但掌握率下降，说明奖励在替代学习，需要削弱奖励，而不是加大奖励。

---

## 7. 红线

以下奖励或做法不允许出现在任何版本中：

- 与邀请、分享、注册、付费、班级人数挂钩的任何奖励。
- 现金、实物、优惠券、充值、学习之外的权益。
- 付费随机、抽奖保底、抽卡式的收费机制。
- 与成绩、评优、综合素质评价挂钩的任何产品奖励，或由产品向学校提交奖励记录用于评价。
- 排名式奖励，或只奖励前几名的机制。
- 以奖励为条件的强制任务，例如"完成奖励才能继续下一单元"。
- 以奖励为由推送付费内容或对未成年人施加购买压力。

---

## 8. 上线顺序

- **第一批**：词卡图鉴、单元徽章、地图装饰、据点的伙伴技能卡、每日弹窗上限与收藏箱。
- **第二批**：季徽章、小乐装饰、故事彩蛋、班级集体目标与班级徽章、老师认可卡。
- **第三批**：装饰的小概率随机掉落（需先完成透明度展示）。
